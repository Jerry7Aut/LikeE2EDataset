# 研究内容与评测阶段的对应关系

本文说明评测阶段如何落到研究内容框架的四项任务上，并给出拟解决的关键科学问题、创新点及其在框架中的落点。阶段定义见 [FRAMEWORK.md](FRAMEWORK.md)。

## 0. 科学问题与创新点

### 0.1 拟解决的关键科学问题

**（5）漏洞修复与对抗防御多阶段验证结果的一致性判定**

漏洞修复与对抗防御包含漏洞触发、补丁验证、业务回归、攻击检测、策略处置与变种复测等多个阶段。各阶段的验证对象、输入条件与判定依据不同，同一攻击失败既可能来自漏洞根因消除或防御有效阻断，也可能来自触发条件缺失、验证状态被污染或业务功能受损。只看单个阶段的结果无法区分这几种原因，白盒修复结论与黑盒防御结论之间也可能出现不一致。因此需要解决的关键问题是：如何在同一漏洞场景下组织两条线共享的验证状态与隐藏真值攻击集，使白盒修复与黑盒防御的证据能够逐阶段对照，并在攻击失败时区分根因消除、有效阻断与验证失效，最终形成修复效果、防御效果与业务可用性的统一判定。

框架中的对应机制：

| 歧义来源 | 框架中的消解手段 |
|---|---|
| 攻击失败可能只是触发条件缺失 | 每次重放前确认目标存活并轮换 nonce，环境重置后才开始新阶段；S1 不成立时后续阶段一律 gated |
| 修复成功可能只是业务被打坏 | S2 与 S3 在同一 patched 镜像上连续执行，业务回归失败独立记分 |
| 防御有效与漏检难以区分 | S5 要求告警准确圈出攻击请求对应的 traffic_id，S6 重放同一股攻击流量 |
| 只挡住自己见过的那一条 | S4 用出题人的隐藏变种分别复测补丁与规则 |
| 两条线结论可能互相矛盾 | 同源场景、同一轮 nonce、同一套判据，白盒与黑盒分别记录后对照 |

### 0.2 创新点

**创新点 1：同源漏洞驱动的白盒修复与黑盒防御双轨协同验证方法**

针对漏洞修复与防御验证相互分离、验证条件与判定依据不一致的问题，提出同源漏洞驱动的白盒修复与黑盒防御双轨协同验证方法。围绕同一真实漏洞场景，构建双轨共享的业务流程、验证状态与隐藏真值攻击集，白盒侧开展漏洞触发、补丁语义分析、业务回归及攻击变体复测，验证修复正确性与抗绕过性；黑盒侧重放攻击流量、检测响应、策略处置、业务影响评估及变种攻击复测，验证防御策略有效性。通过同源攻击对照与跨阶段证据关联，区分漏洞根因消除、防御有效阻断和业务异常导致的攻击失败，对双轨不一致结论开展补充验证，形成修复效果、防御效果与业务可用性的统一判定及反馈优化机制。

## 1. 研究内容布局

研究内容框架分为上下两层。上层依次是研究内容 2 修复正确性与抗绕过、研究内容 3 自主防御策略验证、研究内容 4 效能评估与反馈，三列横向衔接。下层是研究内容 1 建模与场景构建，通过场景支撑与状态支撑连接上层三项。

```
研究内容2 修复正确性与抗绕过 ──▶ 研究内容3 自主防御策略验证 ──▶ 研究内容4 效能评估与反馈
          ▲                              ▲                              ▲
          └──────────── 研究内容1 建模与场景构建（场景支撑 / 状态支撑）────────────┘
```

## 2. 总览

| 研究内容 | 对应框架部分 | 主要阶段 |
|---|---|---|
| 1 建模与场景构建 | case 环境与判据 | 无独立阶段，支撑两条线 |
| 2 修复正确性与抗绕过 | 白盒线 | S1、S2、S3、S4 |
| 3 自主防御策略验证 | 黑盒线 | S5、S6、S7、S4 |
| 4 效能评估与反馈 | 评分与报告 | 全部阶段的汇总 |

## 3. 逐项对应

### 3.1 研究内容 1：建模与场景构建

| 研究任务 | 对应实现 |
|---|---|
| 漏洞语义与修复逻辑建模 | `ground_truth/reference_patch.diff` 定义本题缺陷与修复语义，`vulnerable_code` 与 `fixed_code` 存档对照 |
| 攻击利用链与防御行为建模 | `replay.reference_attack_cmd` 提供攻击流量，`variant_cmd` 提供同类变种；NDR 的 `/traffic`、`/alerts`、`/rules` 对应观测与处置行为 |
| 验证场景与状态生成 | compose 拓扑包含 target、gateway、ndr、egress 与流量容器；`reset()` 切换镜像、轮换 nonce、清空流量与规则，保证每次重放独立 |
| 验证效能表征 | flag 型以本轮唯一 nonce 为判据，crash 型以目标容器重放前后的存活状态差为判据 |

### 3.2 研究内容 2：修复正确性与抗绕过

| 研究任务 | 阶段 | 对应实现 |
|---|---|---|
| 补丁代码特征提取 | 出题环节与被测方 | 参考补丁定义修复语义，被测方提交统一格式的 `patch.diff` |
| 漏洞语义与修复逻辑关联 | S2 前半 | 应用补丁后通过 `patch.build_cmd` 真编译出 patched 镜像 |
| 修复边界与绕过风险分析 | S3、S4 | 业务回归验证合法行为，变种重放验证修复边界 |
| 修复正确性与完备性验证 | S2 与 S4 | S2 验证同一攻击失效，S4 验证同类变种全部失效 |

### 3.3 研究内容 3：自主防御策略验证

| 研究任务 | 阶段 | 对应实现 |
|---|---|---|
| 网络流量面观测 | 环境 | 网关把每条请求的原始字节镜像给 NDR，不含规则命中结果等执行侧结论 |
| 防御验证任务自主规划 | 蓝队两段会话 | 检测阶段读流量决定交哪些告警，处置阶段读告警决定部署哪些规则 |
| 检测与处置能力验证 | S5、S6、S4 | S5 验证告警指向攻击流量，S6 验证攻击被阻断，S4 验证变种同样被阻断 |
| 防御缺陷定位与能力诊断 | 失分归因 | S5、S6、S7、S4 失败分别对应漏检、未阻断、业务误伤、泛化不足 |

### 3.4 研究内容 4：效能评估与反馈

| 研究任务 | 对应实现 |
|---|---|
| 防御效能指标体系构建 | 阶段定义与固定分母，白盒 4 项、黑盒 4 项，两条线各占一半 |
| 多维验证数据关联 | 同一轮黑盒评测中的 S5 检测、S6 处置、S7 业务与 S4 泛化结果联合分析 |
| 防御效能智能分析与判定 | 区分 `gated` 与不计分：前者记 0，后者表示设施失败并使最终分为空 |
| 防御策略反馈优化 | 尚未形成闭环，结果只生成报告，不回写题面与环境 |
